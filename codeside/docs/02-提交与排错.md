# 提交与排错

## 必须遵循的接口

- 交付一个 Python 源文件，只用标准库，不依赖开发包内的 arena 模块或其他外部文件。策略可以把需要的算法代码写入同一个文件。
- stdin 每行一条 JSON；stdout 每行一条 JSON 并 flush。调试输出放 stderr。
- init 回复 `{"ready": true}`；turn 回复 `{"tick": 收到的tick, "actions": {...}}`。end 后正常退出。
- 一个进程控制一整队。2v2 也只提交一个文件，要遍历所有己方存活单位。
- 单位 ID 不是数组下标。按 player_id 与 my_id 区分敌我，actions 的键用字符串形式的单位 ID。
- 不依赖出生在左侧、不写死地图种子或队伍人数。tiles[x][y] 从左下角开始，y 向上；人物 position 是脚底中点。
- properties / level 只在 init 中发送；模板负责把它们附回 game。
- 遵守禁止联网、读写外部文件、启动子进程的参赛约束。模型 API 只用于赛前生成代码，比赛中的机器人不能调用 API。
- 正式评测会使用新的地图种子。公开练习种子 12、21、34 是调试用例，不是完整测试集。

## 什么算通过自测

本包新增的 kit.py check 检查三个赛段、两侧出场，测试动作形状和每场运行稳定性。崩溃、非 JSON 对象输出、任意一次单 tick 或整局 CPU 预算超限 会失败。任何短局通过都不意味着能完成所有正式地图，也不表示强于基准。

本说明统一使用 kit.py check；主办方还会按正式配置复测。

## 常见故障

| 现象 | 检查事项 |
|---|---|
| 不动、超时 | 是否每条回复 flush，是否回显正确 tick，是否超出时间预算 |
| 2v2 只控制一个人 | 应遍历所有 player_id == my_id 的单位 |
| 右侧出生失效 | 不要固定向右移动，地图坐标不会为玩家翻转 |
| 输出看起来正确但无动作 | actions 必须是对象，键是单位 ID 字符串；不能输出 Markdown 代码围栏 |
| 改了代码无法打包 | 重新运行 check，报告绑定代码 SHA-256 |
| 终端中文乱码 | 可设置 PYTHONUTF8=1；报告和文档均为 UTF-8，JSON 中数据不受终端字体影响 |
| 带空格的路径失效 | 优先用 kit.py，参数路径用引号包住，例如 --bot "我的策略/bot.py" |

## 成绩与版本

单局按游戏得分判断胜负，再记胜 3、平 1、负 0 的赛事积分。所有 AI 都参加三个赛段，不设中途淘汰。赛段得分 = 赛事积分合计 ÷ 该赛段完成场数；AI 总分 = (round1 得分 + round2 得分 + finals 得分) ÷ 3。总分范围 0–3，按精确值降序排名，同分并列。

三个赛段使用相同地图轮数；每轮全体选手两两同图换边。须完成三赛段完整赛程后汇总，不将缺项补零。主办方使用 standings.py 生成最终总榜，单个赛段页面的分差等统计不作为最终排名依据。

本版循环赛每一轮使用 base_seed + round_index；同轮所有组合及交换左右侧使用同一地图种子。每轮有 N × (N−1) 场。换边不会保证双方战术对称，但消除了换边时换地图的问题。

正式参赛资格、生成代码的时间/次数、是否允许人工改动、隔离运行环境、比赛轮数和重赛规则，由赛事公告冻结。所有选手使用同一份模板和材料。

主办方运行时会重算代码摘要并重新校验，不以选手自带的 passed 字段直接确认资格。不要把自测报告当作签名证书。
