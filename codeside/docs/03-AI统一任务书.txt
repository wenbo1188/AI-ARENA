平台射击 AI 竞赛 · 统一任务书 v1.2

任务：编写一个独立的 Python 机器人，在随附的平台射击竞技场中控制己方所有单位，尽可能通过伤害和击杀获取更高得分。最终交付一个可直接运行的 bot.py，只依赖 Python 标准库。

比赛赛制：所有 AI 参加三个赛段的同图换边循环赛。每场胜 3、平 1、负 0；每个赛段先计算场均积分，最终总分为三个赛段得分的等权平均（0–3 分），总分相同并列。伤害与击杀的游戏得分只决定单场胜负，不直接计入总平均分。

先阅读同包 docs/05-比赛规则与参赛手册.md 了解比赛，再查阅 docs/01-参赛规则与接口.md 和 entry/bot.py。单文本材料已附规则与接口全文。按本包参赛规则、JSON 协议和 init.properties 编写程序。正式赛事对代码来源和人工干预的限制由主办方另行公布。

必须兼容 round1（Simple 1v1）、round2（Simple 2v2）、finals（Complex 2v2）及左右两侧出场。所有己方单位由同一个进程控制；不要固定单位 ID、地图种子、出生方向或队伍人数。

使用 stdin/stdout 逐行 JSON。init 回复 {"ready":true}；每个 turn 回复含同一 tick 和 actions 对象的 JSON，动作以单位 ID 的字符串为键；每次立即 flush；收到 end 后退出。debug 写 stderr，stdout 不能含解释、日志或代码围栏。不能联网、访问外部文件或运行子进程，不能修改评测器或读取对手文件。

统一运行预算：每 tick 现实时间上限 1000 ms；每个策略进程的整局 CPU 时间预算为 20 × max_tick_count + 20000 ms。默认 3600 tick 对应 92000 ms（92 秒），提前结束不缩减预算。CPU 时间包括程序启动、初始化、JSON 收发处理和全部策略线程的用户态与内核态计算，不计睡眠等待或裁判进程耗时。 init 与首个 turn 共用首次 1000 ms 响应窗口，没有额外的初始化宽限；后续每个 turn 单独计现实时间。2v2 的两个己方角色由同一个进程控制，共享该进程的预算。 内存上限 256 MiB。任一时间上限超出后进程终止，不再控制角色。默认最多 3600 tick、每 tick 100 次物理子更新；实际参数以 init 为准。

如果有本地运行工具，完成后执行 python kit.py check，并用更长的比赛检查稳定性。没有执行环境时，明确标注未实际测试，不得编造胜率或通过记录。

有文件交付能力时，提交 bot.py，附一段策略简介和实际验证情况。只能文本输出时，给出一个完整的 Python 代码块，主办方会去掉围栏保存为 bot.py；禁止省略代码、留下 TODO 或要求调用外部服务。

给所有模型的任务正文、规则附件、基准、生成预算和可用工具应保持一致。模型名称/版本由主办方记录，不由策略在比赛中探测。尚未冻结的赛事条件见主办方公告。
