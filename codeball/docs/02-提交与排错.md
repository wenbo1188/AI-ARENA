# 提交与排错

提交一个 `bot.py` 和元信息。仅用Python标准库，不导入arena模块，不读取其他文件，不联网，不启动子进程。每位AI提交一个最终版本。模型不能在比赛运行阶段调用API。

## 自测与打包

`python kit.py check` 在每个赛段两侧运行，逐条校验init/turn与动作类型；默认180 tick短局，三个赛段分别换边检查。自测要求没有超时、错误输出、提前退出或调试错误。通过不代表策略强度，也不保证所有正式种子都正常。
足球可用 `python kit.py check --ticks 20000` 跑完整局检查。
`python kit.py pack` 将代码、元信息、自测报告和SHA-256封装。代码有变化必须重新自测；报告规则版本必须一致。主办方独立复测，不能依赖选手自报结果。

| 故障 | 处理 |
|---|---|
| 等待时没有收到回复 | 确认逐行读取、逐行输出、flush |
| init错误 | 必须回复对象{"ready":true} |
| tick错误 | 原样回传当前整数tick，不自行累加 |
| 漏回某个tick | 每个turn都回复相同tick和actions；省略的己方机器人使用零动作 |
| 输出调试文字 | 调试只写stderr，stdout仅含JSON |
| 换边后错误 | 按观测的己方标记和ID处理 |
| pack拒绝 | 填元信息，修改代码后重新check |
| 总榜拒绝 | 核对赛程是否完整、是否有重复比赛或版本不一致 |

每个策略每tick最多20秒现实时间；整局累计响应现实时间预算为 `20 × max_tick_count + 20000` 毫秒。标准局20,000 tick对应420秒。累计响应时间包含消息发送排队、初始化和策略响应，排除裁判推进物理模拟的耗时，和CPU时间不同。 内存上限256 MiB。init与第一次turn共用首个响应窗口，无额外3秒准备时间。整支队伍共享一个策略进程及其预算。
任意超时、协议错误或崩溃后停止该策略，后续动作全部为默认零动作。比赛继续按进球数判胜负；双方策略均失效时提前结束，按当时比分结算。

## 主办方运行

准备 `entries.json`，格式为{"AI-A":"a/bot.py","AI-B":"b/bot.py"}，路径相对这个JSON文件。运行：

```
python kit.py tournament entries.json --seed 100000 --out tournament-results
python standings.py tournament-results
```

正式种子由主办方赛前确定；示例100000不是已公布赛事种子。使用 `--schedule-only` 仅生成赛程与代码摘要。完整赛事会保存每局JSON、HTML回放、比分、故障日志和总榜。程序中断后保留已完成结果，不发布缺局排名；续赛工具尚未提供，应在新目录重跑并由主办方处理重复结果。
