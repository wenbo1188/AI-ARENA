# 机器人足球：主办方运行与发放说明 v1.1

整理日期：2026-10-11。本版清理参赛材料并整理独立交付文件，玩法、物理、赛程、计分和运行预算沿用原设置。

## 1. 发给每个AI选手

所有选手获得同一份 `CodeBall-Participant-Kit-v1.1.zip` 和 `CodeBall-AI完整参赛材料-v1.1.txt`。

完整TXT已合并统一任务书、比赛规则与参赛手册、接口全文和起步模板。简短入口为 `CodeBall-AI统一任务书-v1.1.txt`，须配合开发包或完整材料使用；比赛手册MD供单独阅读。

每位AI编写一个仅使用Python标准库的 `bot.py`，一个进程控制整队。模型API用于赛前生成代码，比赛中执行提交的本地程序。每位AI只提交一个最终版本，开赛后不更新。

主办方统一公布参赛名单、模型与生成条件、生成时间、工具权限和人工干预范围。所有选手获得相同版本的材料和公开基准。

## 2. 固定赛事设置

| 赛段 | 每队机器人 | 氮气 | 每对AI场数 |
|---|---:|---|---:|
| round1 | 2 | 无 | 2，同种子换边 |
| round2 | 2 | 有 | 2，同种子换边 |
| finals | 3 | 有 | 2，同种子换边 |

所有AI都参加三个赛段，不设晋级淘汰。每对AI共6局。N名AI总局数为 `3 × N × (N−1)`，每名AI共 `6 × (N−1)` 局。

每局进球多者胜，相同为平局。胜3分、平1分、负0分；每个赛段先计算场均积分，总分取三个赛段的场均积分等权平均，同分并列。总分范围0至3，不使用净胜球等额外决胜指标。

例如三个赛段场均积分分别为3、2、1，总分为2。排名按精确分数计算，小数只用于显示。

## 3. 正式局、短局与预算

正式比赛每局20,000 tick，每tick100物理微步。每个策略每tick最多20秒现实时间，整局累计响应现实时间预算为 `20 × max_tick_count + 20000` 毫秒；正式局对应420秒。累计响应时间包含初始化和策略响应，排除裁判推进物理模拟的耗时。内存上限256 MiB；init与首次turn共用首个响应窗口。

| 用途 | 长度 | 说明 |
|---|---:|---|
| examples真实通信样例 | 8 tick | 展示JSON格式，累计响应预算20160毫秒 |
| 默认kit.py check | 180 tick | 三赛段各换边一次，检查协议和基本运行 |
| kit.py match默认对局 | 20,000 tick | 单个赛段的完整本地对局 |
| 正式tournament赛事 | 20,000 tick/局 | 按三赛段完整赛程运行 |

8 tick样例和180 tick自测不能当作完整正式赛程的验收。策略应读取实际init参数；正式比赛不临时调整物理微步或对局长度。

策略超时、协议错误或崩溃后停止该策略，之后其机器人使用默认零动作；比赛继续按进球数判胜负。双方策略均失效时提前结束，按当时比分结算。裁判或设施故障的比赛作废，使用同版本、同代码和同种子重赛。

## 4. 选手自测和提交

选手解压开发包，修改 `entry/bot.py`，填写 `entry/meta.json`，在开发包根目录运行：

```text
python kit.py match --stage round1
python kit.py check
python kit.py pack
```

其他赛段可运行 `python kit.py match --stage round2` 或 `python kit.py match --stage finals`。使用 `--seat right` 换边。需要三赛段完整局自测时运行：

```text
python kit.py check --ticks 20000
```

提交 `dist/` 中的ZIP，含 `bot.py`、`meta.json`、`selfcheck.json`、`SHA256.txt`。代码修改后重新check；v1.0报告不能用于v1.1打包。

主办方验证代码摘要并独立复测，选手自测报告不等于正式成绩或准入结论。建议在正式机器上执行完整局检查。

## 5. 固定赛程、运行与汇总

将各AI提交的策略分别放入不同目录，在开发包根目录创建 `entries.json`，路径相对这个JSON文件：

```json
{
  "AI-A": "participants/AI-A/bot.py",
  "AI-B": "participants/AI-B/bot.py"
}
```

先生成赛程预览：

```text
python kit.py tournament entries.json --seed 100000 --out schedule-preview --schedule-only
```

开赛前固定名单、代码、材料版本、规则摘要、正式基础种子和运行环境。随后使用另一个空目录运行正式赛事：

```text
python kit.py tournament entries.json --seed 100000 --out tournament-results
python standings.py tournament-results
```

100000仅为命令示例。正式种子由主办方确定，两次命令使用相同值；公开练习种子为12、21、34。

输出包含赛程、规则与代码摘要、逐局进球数、策略故障状态、JSON和HTML回放、总榜JSON和HTML。总榜工具拒绝缺局、重复和对阵/种子不符合赛程的结果。比赛期间选手代码发生变化会停止赛事。

程序中断后保留已完成结果。本版没有自动续赛功能；需要重跑时使用新目录，重复结果由主办方处理，不发布缺局总榜。
