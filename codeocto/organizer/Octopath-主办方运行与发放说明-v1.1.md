# 旅人对决：主办方运行与发放说明 v1.1

定版日期：2026-10-09。

## 一、给每个AI选手什么

所有选手收到同一份 `Octopath-Participant-Kit-v1.1.zip` 和 `Octopath-AI完整参赛材料-v1.1.txt`。将完整材料中的任务书作为统一要求，让AI读取规则、生成一个Python策略，并在开发包中自测和打包。

完整材料已包含统一任务书、比赛手册、完整接口和起步模板，无需另外拼接旧版说明。可单独查看 `Octopath-比赛规则与参赛手册-v1.1.md`；简短入口是 `Octopath-AI统一任务书-v1.1.txt`，它需要配合开发包全文使用。

每位AI只提交一个最终版本。模型调用用于赛前生成代码；正式对局只执行提交的本地程序。所有选手的生成时间、模型配置、工具权限和人工干预范围由主办方统一公布。不要向个别选手额外提供策略建议或私有对手代码。

## 二、本版固定规则

| 项目 | 设置 |
|---|---|
| 赛段 | single，4v4，双方同时隐藏选人与配置 |
| 最大HP | 每名角色配置计算后固定加1000，满血开局 |
| 奥义 | 第一回合可用，仍需满足SP、3 BP和技能条件 |
| 潜力与伤害 | 开局满潜力支援保持100%；使用正常伤害公式 |
| 每对AI | 固定打完5局，不提前结束，不因平局补赛 |
| 出场位置 | 每对交替3:2，额外位置按整个名单平衡 |
| 时长 | 最多30回合 |
| 胜负 | 全员倒下判负；到上限比较全队当前HP/最大HP比例之和 |
| 积分 | 胜3、平1、负0；全部正式对局场均积分排名，同分并列 |
| 预算 | 每步1秒现实时间，整局60秒CPU，256 MiB内存 |
| 开局窗口 | init与首次turn共用1秒窗口 |
| 策略故障 | 停止该策略，之后默认行动；按最终战况判胜负 |
| 练习种子 | 12、21、34 |

N名AI共打 `5 × N × (N−1) / 2` 局，每名AI参加 `5 × (N−1)` 局。总榜满分为3分。比如2胜2平1负累计8分，场均1.6分。

固定增加的1000HP在副职百分比和支援技能固定加值之后加入；它不占任何赛前预算。恢复、复活、中毒、潜力增长和回合上限判定中涉及最大HP的计算使用最终最大HP。

## 三、接收和复测提交

选手先修改 `entry/bot.py`，填写 `entry/meta.json`，在开发包根目录运行：

```text
python kit.py match
python kit.py check
python kit.py pack
```

提交的是 `dist/` 中生成的ZIP，含 `bot.py`、`meta.json`、`selfcheck.json`、`SHA256.txt`。修改代码后必须重新check。v1.0报告不能用于v1.1提交。

主办方校验提交摘要，分别提取到不同选手目录，再使用本版开发包执行同样的 `check --bot 路径` 进行独立复测。自测通过表示样例流程和协议正常，不表示策略强度或所有正式种子都已验收。

## 四、生成赛程与运行赛事

在开发包根目录准备 `entries.json`，路径相对该JSON文件：

```json
{
  "AI-A": "participants/AI-A/bot.py",
  "AI-B": "participants/AI-B/bot.py"
}
```

先生成赛程，正式开赛前固定选手代码、开发包完整性摘要、种子和运行环境：

```text
python kit.py tournament entries.json --seed 100000 --out schedule-preview --schedule-only
```

确认后使用另一个空目录运行：

```text
python kit.py tournament entries.json --seed 100000 --out tournament-results
python standings.py tournament-results
```

这里的100000仅为演示。正式基础种子由主办方确定，并在两次命令中使用相同值。不要把练习种子用作全部正式赛程。

输出包含赛程和版本摘要、每个选手代码摘要、逐局结果与故障记录、独立JSON及HTML回放、总榜。总榜工具拒绝缺局、重复和种子不符合赛程的结果。比赛期间修改选手代码会停止赛事。中断后保留已完成文件；当前没有自动续赛工具，重跑使用新目录，重复结果由主办方处理。

裁判或运行设施故障的比赛作废，以同一版本、同一代码、同一种子重赛；不能将裁判故障计为策略故障。

## 五、版本交接与验收

本次发放使用v1.1。v1.0保留为历史材料，不再与新包混用。Windows/Python 3.12为本次验证环境；若正式赛事用Linux，应在该机器上复测运行预算、内存限制和回放输出，并固定硬件与并发安排。

开发包内包含原始引擎、三个公开基准、起步文件、真实JSON样例、规则和接口全文、离线示范回放、自测及打包工具、总榜工具、测试、许可与素材来源、版本及完整性清单。

本版沿用全员加1000HP的已确认方案，仍可能出现开场单人击倒或整队重伤；功能验收不等于所有阵容均衡。之前平衡对比中的贪心基准使用集合遍历，同分动作可能受Python字符串哈希顺序影响，不能当作严格逐局配对实验。v1.1已固定基准同分动作顺序，后续比试应统一基准版本与运行设置。开场真实复现不依赖该基准选择，仍可按保存的配置验证。

验收详情见 `Octopath-开发包验收记录-v1.1.json`。平衡验证和问题复现属于主办方资料，不作为给AI选手的额外策略提示。
